# 인터넷을 믿지 마세요 (trust-no-internet)

뉴스·커뮤니티의 긍정/부정 신호를 지수화하고, 그 신호를 그대로 따라 매매했을 때
자산이 어떻게 변하는지를 보여주는 공개 웹 서비스.

> 이 프로젝트의 결론은 "감성으로 돈을 벌 수 있다"가 아니다.
> **비용을 반영하고 나면 계좌가 어떻게 녹는지**를 보여주는 것 자체가 콘텐츠다.

## 청사진 v0.3

### 데이터 플로우

```
[L0 수집]  google_news_rss(백필·다국어) · naver_news 스크래핑(최근 구간)
           naver_search_api(일간 증분 전용) · naver_board(종토방, 커버리지 제한)
           fourchan(/biz/, 백필 불가 — 매일 실행 필수)
             ↓ body_hash 계산 후 raw_documents에 임시 저장
[L1 정규화] 제목 정규화 → title_hash(완전일치) → simhash(근사) → rapidfuzz 확정
             ↓ dup_group_id 부여, 대표만 is_canonical=1
[L2 채점]  대표글 중 여론 채널만 LLM/FinBERT → {positive, negative, neutral, irrelevant}
             (vendor·algo·pr·aggregator 는 가중치 0이라 채점 자체를 건너뛴다)
             ↓ 성공 시 raw_documents 행 삭제 (본문 파기)
[L3 영구]  documents — 날짜/매체/등급/라벨/제목/확산도
             ↓
[L4 집계]  sentiment_daily (code × date × media_id)
             ↓  tier 롤업은 sentiment_daily_tier 뷰로
[L5 서빙]  FastAPI — 가중치는 조회 시점 파라미터
[L6 UI]    일/주/월 가격차트 + 매체별·등급별 감성 + 자산곡선
```

### 확정된 설계 결정 11가지

| # | 결정 | 근거 |
|---|---|---|
| 1 | 시각은 **UTC로 저장**, KST 변환은 조회 계층 | 구 프로젝트는 소스별 naive/aware 혼재로 +9h 오차 |
| 2 | 본문은 `raw_documents`에 임시 저장, **파기 전 `body_hash`** | 파기 후에는 중복판정 능력을 영구히 잃음 |
| 3 | 집계는 **media 단위**, tier 롤업은 뷰 | 매체별 차트 요구 충족. tier 대비 행 수 21배(실측) |
| 4 | 중복은 삭제하지 않고 **`is_canonical=0` 강등** | 재배포 횟수(확산도)가 독립 피처 |
| 5 | 라벨에 **`irrelevant` 4번째 클래스** | "카카오톡 잡담"이 neutral로 흡수되어 지수를 0으로 끌어내림 |
| 6 | **`prompt_version`/`label_model` 기록** | 프롬프트 교체 시 과거/신규 라벨 혼재 → 인공적 regime shift |
| 7 | 신호 윈도우 `[D-1 15:30, D 08:50]` → **D일 시가 체결** | "익일 시가"로 미루면 하루를 이중으로 낭비 |
| 8 | 거래비용은 **`fee_schedule` 테이블** | 거래세율은 연도별 변경. 하드코딩 금지 |
| 9 | `coverage`에 **`partial`/`empty` 상태 분리** | 부분 수집을 완료로 찍으면 그 날짜가 영구히 반쪽으로 고정 |
| 10 | 가중치 0 채널은 **채점도 하지 않는다** (`NON_OPINION_CHANNELS`) | 지수에 1도 기여하지 않는 문서에 LLM 호출의 31%를 쓰고 있었다 |
| 11 | 화면에 **채점률(`labeled_ratio`)을 함께 싣는다** | 라벨률 2%와 99%가 같은 표에 서면 채점 진척도를 시장 특성으로 오독한다 |

### 감성지수 산식

```
온도지수 T(t) = (pos−neg)/(pos+neg) × n/(n+k)        # 방향 × 표본신뢰도, k=10
관여도   E(t) = z( log(1+doc_cnt) )                   # 방향과 무관한 "관심 온도"
확산도   D(t) = Σ spread_sum                          # 재배포 횟수 = 파급력
백테스트 신호 = Σ w·(pos − neg)                        # 표시용과 달리 순건수를 쓴다
```

`w`는 `media.tier` → `DEFAULT_TIER_WEIGHTS` 매핑이며 **조회 시점 파라미터**다.
슬라이더를 움직여도 재집계하지 않는다.

### 채점률을 화면에 싣는 이유 (실측)

감성지수는 라벨이 붙은 문서만으로 만들어지는데, 채점은 발행일 역순으로 진행된다.
따라서 채점이 밀린 시장의 지수는 "그 시장의 여론"이 아니라 **최근 구간에 쏠린
일부 문서**를 재고 있다. 2026-08-24 채점 전후 실측:

| 시장 | 채점 전 | 채점 후 | 시차 상관 (채점 전 → 후) |
|---|---:|---:|---|
| BTC | 6% | 98% | lag+2 r=+0.644 (변화 없음) |
| ETH | 2% | 99% | lag+3 r=+0.577 → lag+2 r=+0.650 |
| SPX | 2% | 97% | **분석 불가** → lag+1 r=+0.585 |
| NASDAQ | 47% | 98% | lag−4 r=−0.450 → lag−4 r=−0.437 |

NASDAQ이 이 장치가 필요한 이유를 그대로 보여준다. 채점률 47%에서 `lag=−4,
r=−0.450`, 즉 **"여론 선행 + 역행"** 이라는 이 사이트의 가설을 정확히 뒷받침하는
가장 탐나는 신호가 나왔다. 절반의 문서로 나온 숫자였으므로 그대로 결론으로
내걸었다면 근거 없는 주장이 됐을 것이다. 전수 채점 후에도 −0.437(차분 후 −0.303)로
남았으니 이번에는 진짜였지만, **그 사실은 채점을 끝낸 뒤에야 알 수 있었다.**

그래서 `MIN_LABELED_RATIO = 0.60` 미만인 시장은 결과를 내되 화면에서 격리한다 —
표에 ⚠ 표시, 시차 곡선은 점선, 그리고 **"유의한 시장 N곳" 요약 집계에서 제외**한다.
마지막 항목이 핵심이다. 미완 시장을 요약에 넣으면 그 문장 자체가 채점 진척도의
함수가 되어, 채점을 더 돌릴 때마다 사이트의 결론이 바뀐다.

### 축소항 k가 필요한 이유 (실측)

| 하루 글 수 | 일수 | \|극성\| 평균 | ±1.0 극단값 |
|---|---:|---:|---:|
| 1~5건 | 129 | 0.725 | **62.8%** |
| 6~20건 | 132 | 0.575 | 22.0% |
| 21~100건 | 52 | 0.570 | 11.5% |
| 100건+ | 21 | 0.391 | **0%** |

축소항이 없으면 **차트에서 가장 크게 튀는 날이 근거가 가장 빈약한 날**이 된다.
긍정 1건·부정 0건이면 +1.0으로, 긍정 300·부정 200인 날(+0.2)보다 5배 낙관적으로
보인다. k=10에서 극단값이 사라지고 지수 범위(최대 0.89)는 유지된다.

### 글 수를 지수에 넣어야 하는가 — 넣어야 한다 (실측)

지수와 익일 시가수익률의 상관 (이상치 제거 후):

| 산식 | SK하이닉스 | 카카오 |
|---|---:|---:|
| 극성만 | −0.118 | +0.021 |
| **순건수 (글 수 반영)** | **−0.247** | **−0.130** |

글 수를 반영하면 신호가 약 2배가 된다. 부호가 음수인 것은 **여론과 주가가
역행**한다는 뜻으로, 이 사이트의 논지와 일치한다. 하이닉스는 |z|=2.6으로
유의하고 카카오는 |z|=1.8로 경계선이다 — 종목마다 다르다는 것 자체가 관찰 결과다.

### 알려진 부채

- **종토방 커버리지 불균형** — 대형주는 하루 2만 건이 올라오는데 게시판
  페이지네이션이 1,001p에서 끊긴다(실측 SK하이닉스 19,279건 = 1.5일치).
  뉴스는 180일을 덮으므로 켜두면 그 이틀이 6개월 곡선을 지배한다.
  → `community` 기본 가중치를 **0**으로 두고, UI에 사유를 노출한다.
  균형 잡힌 커뮤니티 소스를 확보하기 전까지 유지.
- **매체 등급 미분류 17.0%** — 롱테일. 등록도메인 단위로 접어 매칭하는데도
  남는 해외 소형 매체가 대부분이다.
- **해외 지수는 수집분의 절반 이상이 여론이 아니다** — 미채점 잔량 기준
  NASDAQ은 제외 채널(aggregator 1,662 + algo 801 + pr 335 + vendor 610)이
  채점 대상(2,803)에 육박했다. 한국 종목(000660은 제외분 0)과 수집 구성이
  근본적으로 다르므로, 시장 간 비교에서 "시장마다 다르다"를 읽을 때 감안해야 한다.
- **영어 지수 질의는 무관 비율이 높다** — 실측 SPX 57.7% / NASDAQ 53.6%
  (한국 종목 news는 그보다 낮다). 질의어가 넓어 `irrelevant`가 걸러내고 있다는
  뜻이지만, 질의 자체를 좁히면 표본이 늘어날 여지가 있다.
- **수집 완전성(`coverage.partial`)이 종목마다 크게 다르다.** `partial`은 "그 날짜를
  끝까지 훑지 못했다"는 뜻이고, 응답 상한에 걸린 날이 그렇게 남는다. 실측:

  | code / source | partial 비중 |
  |---|---:|
  | 035720 / naver_news | **100%** (43일) |
  | NASDAQ / google_rss | 71% (84일) |
  | KOSDAQ / google_rss | 64% (84일) |
  | ETH / google_rss | 55% (84일) |
  | BTC / google_rss | 39% (176일) |
  | KOSPI / google_rss | 32% (84일) |
  | 005930 / google_rss | 28% (366일) |

  **이것이 지수 자체를 오염시킨다.** 백테스트 신호는 극성이 아니라 순건수
  `Σ w·(pos − neg)`이고 관여도는 `E = z(log(1+doc_cnt))`인데, 상한에 걸린 날은
  건수가 100에서 잘린다. "여론이 폭발한 날"과 "상한에 걸린 날"이 구분되지 않고,
  편향이 무작위가 아니라 **신호가 가장 강한 날에 집중된다.**
  `healthcheck`가 상시 감시한다. 우회 수단은 별칭 확장(질의당 100건이 따로 나온다)뿐이다.
- **`v.daum.net` 1,402건** — 포털 집계 링크라 원 매체를 알 수 없다.
- **005930은 별칭·제외어가 비어 있다.** `aliases_json`이 `["삼성전자"]` 하나뿐이고
  `exclude_json`은 NULL이다. 실측 백필에서 `offtopic: 0`이 나왔는데 이는 오탐이
  없다는 뜻이 아니라 **거를 규칙이 없다**는 뜻이다(035720은 같은 경로에서 52%를
  걸러냈다). `삼성전자우`·`삼성전자서비스` 같은 별개 대상이 섞여 있다.

## 사고 기록: 인코딩 파손 (재발 방지)

`finance.naver.com`은 페이지마다 인코딩이 다르다.

```
/item/news_news.naver  → charset=EUC-KR
/item/board.naver      → charset=UTF-8    ← 종목토론방
```

구 코드가 두 페이지 모두에 `encoding="euc-kr"`를 하드코딩해서 종토방 제목
**28,114/28,286건(99.4%)** 이 U+FFFD로 파손됐다. 복원 불가. 그 상태로 LLM 채점까지
나가 **99.1%가 neutral**로 찍혔고(대조군 naver_news 36.9%), 그 결과 "커뮤니티
인간지표" 차트 전체가 노이즈였다.

방어 장치 2개를 넣었다 — `http_utils._resolve_encoding()`(헤더 charset 우선)과
`assert_decoded()`(U+FFFD 비율 초과 시 예외). **인코딩을 호출부에서 지정하지 말 것.**

## 웹 서비스 실행

```powershell
python -m scripts.serve            # http://127.0.0.1:8000
python -m scripts.serve --reload   # 개발 모드
```

기본 바인딩은 `127.0.0.1`이다. 외부 공개는 `--host 0.0.0.0`을 명시할 때만 일어난다.

### 화면 구성

| Zone | 내용 |
|---|---|
| Header | 종목 · 일별/주간/월간 · 기간(데이터 구간/3M/6M/1Y/전체) · 데이터 보유 구간 |
| Zone 1 | 주가 + 감성지수 오버레이. 종합 / 등급별 / 매체별(칩 선택 최대 6개). 데이터 없는 구간은 회색 음영 |
| Zone 2 | ① 정방향·역배팅 ② 보유수량내·무한공매도 ③ **비용 반영(기본 ON)** ④ 등급별 가중치 6개 |
| Zone 3 | **3선 분해** — 순손익 / 주식 평가액 / 현금 잔고 + Buy&Hold. 차트 위에 실질 수익률 대표 숫자 |

### 백테스트 계산

```
raw(D)   = Σ_tier w_tier × (pos − neg)        # 중립은 애초에 들어가지 않는다
desired  = ±raw                                # 역배팅이면 부호 반전
delta    = max(desired, −position) | desired   # 보유수량내 | 무한공매도
체결      = open(D)                            # 신호는 D−1 15:30 ~ D 08:50 확정
순손익    = cash + position × close(D)         # 0원 시작, 모든 모드에서 정의됨
```

**시드머니가 없으므로 수익률의 분모는 `최대 소요자본`이다.** 누적 투입금을 분모로 쓰면
매도가 쌓여 음수가 될 때 손실이 +수익률로 표시되고, 0을 지날 때 발산한다.
최대 소요자본 = max(현금 잔고 최저점의 절댓값, 공매도 익스포저 최대값).

그대로 FK이므로 코인은 `code='BTC'`가 된다.

|---|---|---|---|
| index | KOSPI, KOSDAQ, NASDAQ, SPX | krx / us | KS11 · KQ11 · IXIC · US500 |

`calendar`가 단순 라벨이 아니다 — 코인은 휴장일이 없어 주말 감성을 다음 거래일로

각각 다른 기사 집합을 반환하므로, 하나만 쓰면 절반을 놓친다. 중복은 URL UNIQUE로
걸러지므로 겹쳐 돌려도 안전하다. 한국어 질의는 한국 로케일, 영어는 미국 로케일로
자동 분기하고 엇갈린 조합은 요청하지 않는다.

## 데이터 소스별 제약 (구 프로젝트에서 실제로 겪은 것)

- **네이버 검색 오픈API는 백필에 쓸 수 없다.** 쿼리당 1000건 상한(`start<=1000`),
  날짜 범위 지정 불가(`sort=date`만). `days_back`을 키워도 같은 최신 1000건이
  돌아온다. 구 코드가 이걸로 1년치 루프를 돌려 신규 0건을 얻었다. **일간 증분 전용.**
- **Google News RSS는 쿼리당 100건 상한이고, 창 밖 기사를 섞어 100건을 채운다.**
  따라서 "응답이 100건" ≠ "잘렸다". 절단 판정은 반드시 *요청한 날짜 창 안에 든*
  건수로 해야 한다 — 응답 건수로 판정하면 이미 완전 수집한 날짜가 영영 `partial`에
  갇힌다. 실측: 카카오 1일 창에서 응답 100건 중 창내 15건인 날이 흔하다.
- **Google News의 `link`는 리다이렉트라 원문 URL을 알 수 없다.** 본문은 수집하지
  않고 제목만 쓴다. 대신 `<source url>`이 매체명·도메인을 정확히 준다.
- **종목명 모호성은 수집 단계에서 걸러야 한다.** "카카오" 질의는 카카오뱅크·
  카카오페이 기사를 함께 끌어온다(실측 6개월 백필에서 제외 대상이 전체의 40% 수준).
  `stocks.exclude_json`의 제외어를 지운 뒤에도 종목명이 남아야 본 종목 기사로 본다.
- **`cafearticle` 검색엔 게시일 필드가 없다.** `ts_confidence='approx'`로 격리한다.
- **디시인사이드 주식갤러리(`stock_new1`)는 2017-01 이후 사실상 죽은 갤러리다.**
  커뮤니티 소스로 기대하지 말 것.
- **종토방은 대형주 백필이 구조적으로 불가능하다.** 하루 게시량이 2만 건인데
  게시판 페이지네이션이 **1,001페이지에서 소진**된다(실측 SK하이닉스 19,279건
  = 1.5일치). `--max-pages`를 올려도 소용없다 — 크롤러가 `stopped` 사유를
  `cutoff`/`page_cap`/`board_end`로 구분해 어느 레버가 유효한지 알려준다.
- **국내 국고채 금리는 무료 소스가 없다.** `KR10YT=RR` / `KR3YT=RR` / `KR1YT=RR`
  모두 404이고 한국은행 ECOS API는 키 발급이 필요하다. 그래서 채권은 금리가 아니라
  **ETF 가격**으로 담는다(KTB→148070 KOSEF 국고채10년, UST→IEF).
  UST만 금리로 남기면 두 채권이 다른 단위가 되는데, 시차 상관 표는 모든 엔티티를
  `close.pct_change()`로 수익률화하므로 금리 계열만 부호가 반대인 채(금리↑ = 채권가격↓)
  아무 표시 없이 실린다. **ETF는 순수 금리가 아니다** — 듀레이션·보수·추적오차가
  섞인다. [확인 필요]
- **알트코인 지수는 직접 만든 합성 계열이다.** 무료 소스가 없어 XRP·SOL·ADA·DOGE
  4종의 **일간 수익률을 동일가중 평균**해 100에서 체인으로 쌓는다. 가격을 평균하면
  안 된다 — SOL(13만원)과 DOGE(127원)를 평균하면 사실상 SOL 단독 지수가 된다.
  고가·저가는 합성 바스켓에 정의되지 않아(코인별 장중 고점 시각이 다르다) 시가·종가
  범위로만 채운다. **생존편향이 있다** — 오늘 상위인 코인으로 과거를 돌리는 것이다.
- **가격은 pykrx**(비공식 KRX 스크래핑). 키움 OpenAPI+는 32비트 파이썬 + 실계좌
  로그인이 매번 필요해 자동화에 부적합.
- **10년치 백필은 무료 소스로 불가능하다.** Google News RSS 아카이브가 얕다 —
  하루 창 기준 코스피/bitcoin이 2026년 100/78건, 2024년 6/50건, **2016년 3/3건**.
  한국어는 1년만 지나면 사실상 비어 있고 영어는 2022년이 실용 한계다. 빅카인즈는
  유료 전환, GDELT는 레이트리밋으로 검증 실패(`[확인 필요]`).
  → **백필이 아니라 전진 수집이 답이다.** 확보 가능한 만큼만 채우고 오늘부터 매일
  쌓는다. 가설 검증에는 10년이 필요 없다 — 코인은 2~3년에 사이클이 다 들어 있다.
